# Hackers-MUD graphical client (`/hackers-mud`)

A self-contained 2D browser client for the same MUD the BBS terminal plays
(`app/src/Mud/`). Modern neon UI, a tiled top-down room view on `<canvas>`,
click / WASD movement, panels for stats / minimap / quests / inventory, and a
command box that still accepts every MUD verb. It exists so people who just
want to play the game can skip the dial-up terminal.

Live at **`https://bbs.thugs.red/hackers-mud/`** — log in with the same
THUGS(red) BBS handle; it's the same account and the same character.

## How it fits together

```
html/hackers-mud/
  index.php            entry doc (Apache DirectoryIndex) -> HackersMudController::shell
  css/game.css         the whole UI
  js/app.js            boot, login + character-create screens, game loop
  js/net.js            fetch wrapper for /api/mud/*
  js/audio.js          synthesised SFX + ambient beds (+ iOS unlock)
  js/sprites.js        procedural pixel-art draw kit (tiles, actors, item icons)
  js/scene.js          the canvas room view: grid build, movement, particles, fx
  js/ui.js             DOM chrome: top bar, side panels, log, modals
  assets/favicon-*.png generated by assets/hackers-mud/gen.php

app/src/Mud/Api.php                    structured (JSON) snapshot of the world
app/src/Http/Controllers/
  MudApiController.php                 /api/mud/* : login/archetype/state/cmd/logout
  HackersMudController.php             the HTML shell + procedurally drawn og.png / banner.png
```

Routes (registered in `html/index.php`): `POST /api/mud/login`,
`/api/mud/archetype`, `/api/mud/cmd`, `/api/mud/logout`; `GET /api/mud/whoami`,
`/api/mud/state`; `GET /hackers-mud/og.png`, `/hackers-mud/banner.png`.
Auth is `Auth::login()` against the BBS `users` table; the client sends
`X-CSRF` (from the login response) on every POST. A small per-session log
buffer lives in the session (`mudc_log`).

## API contract

- **`GET /api/mud/whoami`** -> `{authed, handle, csrf, hasChar}`
- **`POST /api/mud/login`** `{handle,password}` -> `{ok, csrf, needArchetype, archetypes?}`
- **`POST /api/mud/archetype`** `{choice}` -> `{ok, created, state}`
- **`GET /api/mud/state`** -> `{ok, state}` (or `{ok:false, error:'auth'|'nochar'}`)
- **`POST /api/mud/cmd`** `{cmd}` -> `{ok, lines[], sfx[], state}`

`state` is the big object: `player` (level/hp/energy/xp/money/wanted/stats/
skills/effects…), `room` (name/desc/theme/exits/mobs/items/players/shop/extras),
`inventory`, `equipment`, `quests`, `bounty`, `map` (local cells), `log`,
`ambient`, `time`. Every mob carries a `sprite` key and every item an `icon`
key so the renderer never parses prose.

## Controls

- **Move**: `WASD` / arrows (`Q E Z C` diagonals), or click a tile. Walk into a
  glowing edge to take that exit; a locked electronic exit auto-runs `hack`.
- **Interact**: walk into someone/something, `Space` while facing them, or click
  their card in the right panel. Hostile -> fight, keeper -> shop modal,
  fixer -> jobs, trainer -> `train`, ripperdoc -> `uninstall`.
- **Command box**: any MUD verb (`look terminal`, `board`, `train hacking`,
  `talk rogue about work`, `rest`, `recall`, …).
- `I` inventory · `C` character sheet · `M` map · `Enter` command box · `Esc` close.

The client polls `/api/mud/state` every 6s so tick events (aggro, MaxTac, world
broadcasts, other players) show up without input.

## Assets

All in-world graphics are drawn at runtime in `sprites.js` (original,
procedural, CC0) - no binary sprite files. `scene.js` is structured so a real
CC0 atlas (Kenney / LPC / etc.) could replace the `drawTile` / `drawActor` /
`drawItem` functions with atlas blits keyed by the same names. The share card
(`og.png`, 1200x630) and social `banner.png` (1500x500) are drawn by GD in
`HackersMudController`; favicons come from `php assets/hackers-mud/gen.php`.
